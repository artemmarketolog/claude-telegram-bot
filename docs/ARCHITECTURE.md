# 🏗 Как устроен бот

Node.js 22.13+ (нужен `node:sqlite`), ESM без сборки, одна зависимость — [`@anthropic-ai/claude-agent-sdk`](https://docs.claude.com/en/api/agent-sdk/overview) поверх **установленного** Claude Code CLI. Бот не хранит историю: источник правды — транскрипты Claude Code `~/.claude/projects/<папка>/<sessionId>.jsonl`, общие с приложением Claude и терминалом.

```mermaid
flowchart TD
    Phone[Telegram: темы личного чата] <--> API[Telegram Bot API<br/>облачный или свой Local Bot API]
    API <--> GW[app.mjs → Gateway]
    GW <--> DB[(state.sqlite)]
    GW --> Runner[ClaudeRunner: Agent SDK]
    Runner --> CLI[claude CLI · вход по подписке]
    CLI <--> T[(транскрипты ~/.claude/projects)]
    App[Приложение Claude / терминал] <--> T
    GW -. зеркало и список сессий .-> T
    GW -. ~/.claude/sessions + /proc .-> App
```

| Файл | Ответственность |
| --- | --- |
| `app.mjs` | Конфиг из `.env`, отказ стартовать с API-переменными Anthropic, умолчания модели из `~/.claude/settings.json`, polling, остановка по SIGTERM |
| `lib/gateway.mjs` | Темы, лобби, смена проекта, команды, кнопки, карточка хода, очереди, вопросы, зеркало сессий приложения, автотемы, восстановление после рестарта |
| `lib/claude.mjs` | `ClaudeRunner`: один процесс CLI на сессию, потоковый ввод, interrupt, контекст, модели; `childEnv()`; `chatTitle()` |
| `lib/desktop.mjs` | Только чтение: список сессий, реестр живых процессов CLI (проверка через `/proc`, только Linux), новые записи транскрипта, SIGTERM простаивающего процесса |
| `lib/format.mjs` | Карточка статуса, итоговая строка, имена и иконки тем — чистые функции |
| `lib/projects.mjs` | Проекты из `projects.json` |
| `lib/telegram.mjs`, `lib/media.mjs`, `lib/state.mjs` | Bot API с троттлингом и откатами формата, приём файлов и голоса, SQLite |
| `scripts/doctor.mjs` | Самопроверка установки |

## Только подписка

- Процесс Claude получает **пересобранное** окружение: `HOME`, `USER`, `PATH` из login-shell, `LANG`, `XDG_RUNTIME_DIR`, `CLAUDE_CODE_ENABLE_ASK_USER_QUESTION_TOOL=1` и маркер `CLAUDE_TELEGRAM_BOT=1`. Токен бота, ключ OpenAI и любые `ANTHROPIC_*` туда не попадают, поэтому CLI может авторизоваться только входом `claude auth login` (подписка Pro/Max).
- `app.mjs` не стартует, если в окружении есть `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` или `CLAUDE_CODE_OAUTH_TOKEN`.
- Каждый `system/init` проверяется: `apiKeySource` должен быть `none`, иначе процесс закрывается, а тема получает `✗`.

## Сессия и процесс

- Новый чат: UUID заранее, `sessionId` в SDK и имя сессии = заголовок, поэтому связь тема ↔ сессия известна до первого ответа. Существующая сессия: `resume`.
- Опции как у приложения: `bypassPermissions`, `settingSources: user, project, local` (CLAUDE.md, навыки, плагины, хуки), пресет системного промпта плюс короткое дополнение про Telegram и ссылки на файлы.
- Обычное сообщение во время хода отправляется с `priority: 'next'`: CLI вклеивает его в текущий ход на границе инструментов. `/queue` — отдельный ход после текущего (таблица `turn_queue`).
- `AskUserQuestion` приходит в `canUseTool` даже в `bypassPermissions`: вопросы — сообщения с кнопками, ответ возвращается в `updatedInput.answers`.
- Процесс бота закрывается после 30 минут простоя, если нет фоновой работы и открытого вопроса; следующий запрос поднимает сессию из транскрипта.
- Короткое название: после первого успешного хода чата, начатого в боте, — один ход Haiku по подписке (`tools: []`, `persistSession: false`, `settingSources: []`, та же проверка `apiKeySource`).

## Одна сессия — один процесс (Linux)

Реестр `~/.claude/sessions/<pid>.json` доверяется только при совпадении времени старта процесса с `/proc/<pid>/stat`. Свои процессы бот узнаёт по маркеру `CLAUDE_TELEGRAM_BOT=1` в `/proc/<pid>/environ`.

1. Перед отправкой бот ищет чужой живой процесс сессии (приложение, терминал).
2. Процесс занят — сообщение сохраняется в очередь (`✍`, «после компьютера») и уходит само, когда там закончится ход.
3. Процесс простаивает — бот дочитывает хвост транскрипта, останавливает процесс SIGTERM и продолжает сессию сам с той же моделью.
4. `/stop` или `■ Стоп` в теме, где ход идёт на компьютере, останавливает тот процесс — единственный случай, когда бот трогает занятый чужой процесс.

На macOS нет `/proc`, поэтому этой проверки нет (см. ограничения в README).

## Зеркало сессий с компьютера

Каждые 5 секунд для тем с сессиями читаются **новые** записи транскрипта от сохранённого смещения. Записи других клиентов (приложение, терминал) показываются в теме: запрос — свёрнутой цитатой `💻`, действия — на карточке, финальный ответ — сообщением с файлами. Раз в минуту новые сессии приложения Claude в папках под домашней получают тему сами (`pollNewSessions`).

## Очереди и порядок

- Апдейт сначала записывается в `updates` (dedup по `update_id`), offset `getUpdates` сдвигается только после записи. Дальше — отдельный последовательный обработчик на чат: загрузка файла в одном чате не держит другие. Альбом ждёт 1,5 с и уходит одним запросом.
- Кнопки и команды выполняются рядом с polling.
- События Claude сериализуются по чату; `withTurnLock` не даёт пересечься отправке, закрытию хода, очереди и смене проекта; карточка каждого чата правится строго по одной (`cardLock`). Порядок блокировок: ход → зеркало → карточка.
- Исходящие в Telegram — одна очередь на чат владельца (все темы) с интервалом 1,1 с; 429 повторяется.

## Файлы

Входящие файлы сохраняются в `~/.claude-telegram/files/<сессия>/` под безопасными именами; картинки до 3,75 МБ Claude получает как изображения, остальное — абсолютным путём. Ссылки `[имя](/абсолютный/путь)` в финальном ответе становятся вложениями: снимок файла копируется в `files/<сессия>/outputs` и отправляется (до 12 на ответ). `.env`, `~/.claude/.credentials.json`, SSH-ключи, данные Local Bot API и файлы с известными боту секретами не отправляются.

## Данные

| Хранилище | Что |
| --- | --- |
| `state.sqlite: chats` | чат = сессия: папка, проект, тема, модель, статус хода, карточка, контекст, смещение зеркала |
| `topics` | тема ↔ сессия |
| `updates` | входящие апдейты, dedup, удержанные до создания темы |
| `turn_queue` | `/queue` и отложенные «после компьютера» |
| `messages / files / delivered` | привязки сообщений, файлы, маркеры доставки |
| `settings` | offset, лимиты подписки, кэш моделей, умолчания `/model`, иконки тем, кнопки |

SQLite в режиме WAL + `synchronous=NORMAL`; каталоги `0700`, файлы `0600`, `umask 077`. Старые записи чистятся раз в 6 часов.

## Тесты

`npm test` — модульные тесты, `tests/concurrency.test.mjs` (чаты не держат друг друга, гонки на краях хода, автотемы) и `tests/load.test.mjs` — восемь чатов сразу со случайной смесью уточнений, `/queue`, `/stop`, кнопок и задержек Telegram. `LOAD_SEEDS=80 npm test` — длинный прогон.

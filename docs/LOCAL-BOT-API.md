# 📦 Большие файлы: свой Local Bot API

Облачный Telegram Bot API пропускает через ботов небольшие файлы: бот **получает до 20 МБ** и **отправляет до 50 МБ**. Чтобы слать боту длинные видео, архивы и записи созвонов, поставь рядом с ботом официальный сервер [telegram-bot-api](https://github.com/tdlib/telegram-bot-api). С ним файлы ходят **до 2000 МБ в обе стороны**.

Всё делает один скрипт, от тебя нужны только ключи приложения Telegram. Сборка занимает 20–60 минут (зависит от сервера).

## Шаг 1. Ключи приложения Telegram (делаешь ты)

1. Открой [my.telegram.org](https://my.telegram.org) в браузере на компьютере. Введи номер телефона в международном формате (`+7...`) → код придёт **в Telegram** (не СМС) → войди.
2. **API development tools**.
3. Заполни форму: **App title** — любое, например `My files bot`; **Short name** — 5–32 латинских буквы или цифры, например `myfilesbot`; **Platform** — `Other`; остальное можно не заполнять. Нажми **Create application**.
4. На странице появятся **App api_id** (число) и **App api_hash** (32 символа). Передай их агенту или впиши в `.env` бота:
   ```ini
   TELEGRAM_API_ID=<App api_id>
   TELEGRAM_API_HASH=<App api_hash>
   ```

Если форма отвечает просто `ERROR`, это частая болезнь my.telegram.org: выключи VPN и блокировщики рекламы, попробуй другой браузер или зайди через несколько часов. Ключи привязаны к твоему аккаунту — не публикуй их.

## Шаг 2. Установка (делает агент)

Ubuntu/Debian — пакеты для сборки:

```bash
sudo apt-get install -y make git zlib1g-dev libssl-dev gperf cmake g++
```

macOS — нужен Homebrew, остальное скрипт поставит сам.

Затем из папки бота:

```bash
bash scripts/install-local-bot-api.sh
```

Скрипт:

1. переносит `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` из `.env` в отдельный файл `~/.local/share/telegram-bot-api/api.env` (права `600`), чтобы они не попадали в окружение бота;
2. собирает сервер в `~/.local/share/telegram-bot-api` (на Linux проверяет, что памяти хватит: нужно ~4 ГБ RAM + swap, иначе подскажет, как добавить swap);
3. запускает его как сервис только на `127.0.0.1:8081` (systemd на Linux, launchd на macOS);
4. **один раз** выводит бота из облачного API (`logOut`), вписывает `TELEGRAM_API_BASE=http://127.0.0.1:8081` в `.env`, проверяет бота через свой сервер и перезапускает его.

Повторный запуск безопасен: собранный сервер не пересобирается, облачный `logOut` второй раз не выполняется.

Проверка: `npm run doctor` показывает `✅ Большие файлы — свой Local Bot API http://127.0.0.1:8081: файлы до 2000 МБ в обе стороны`.

## ⚠️ Главное правило после переезда

**Никогда не обращайся с этим токеном к `api.telegram.org`**, даже `getMe` из curl или браузера. Любой облачный запрос возвращает бота в облако, и свой сервер перестаёт получать сообщения: бот замолкает. Бот, `doctor` и скрипты сами ходят только в `TELEGRAM_API_BASE`.

Если это всё-таки случилось, останови бота и один раз снова выйди из облака, затем запусти бота:

```bash
set -a; . ./.env; set +a
curl -s -K - <<<"url = \"https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/logOut\""; echo
```

## Как это устроено

- Сервер работает от твоего пользователя и хранит файлы в `~/.local/share/telegram-bot-api/data`. Бот читает полученные файлы прямо оттуда и копирует себе под безопасными именами. Имена папок сервера содержат токен бота, поэтому бот их никому не показывает и оттуда ничего не отправляет.
- Порт слушается только на `127.0.0.1`, наружу ничего не открыто. Логи сервера выключены (`--verbosity=0`): в отладочных логах бывает токен.
- Сервис: `systemctl --user status telegram-bot-api` (Linux) или `launchctl list | grep telegram-bot-api` (macOS).

## Вернуться в облако

1. Останови бота.
2. Выйди из своего сервера: `curl -s -K - <<<"url = \"http://127.0.0.1:8081/bot${TELEGRAM_BOT_TOKEN}/logOut\""`.
3. Удали строку `TELEGRAM_API_BASE` из `.env`, подожди 10 минут и запусти бота.
4. Сервер можно выключить: `systemctl --user disable --now telegram-bot-api`.
